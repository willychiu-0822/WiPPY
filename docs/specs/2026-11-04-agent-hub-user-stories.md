# WiPPY Agent Hub User Stories（草案 v0.2）

- 日期：2026-11-04
- 對應規格：`docs/specs/2026-11-04-agent-hub.md`（v0.1，會依本文件修正）
- 狀態：等使用者確認理解是否正確

## 角色

| 角色 | 說明 |
|---|---|
| 我 | WiPPY 擁有者，唯一的人類使用者 |
| Grok Bot | xAI 的 Agent。WiPPY 可以主動呼叫它；它也可以透過 MCP 或 API 呼叫 WiPPY |
| Instinct | 個人 Agent。WiPPY **無法主動呼叫**它；它用專屬帳號登入 WiPPY 後台，**定時進來看**並執行動作 |
| 群組成員 | LINE 群組裡的人，會收到訊息、點開連結 |

## 已確認的決定

- Instinct 第一階段就要做，用「後台帳號」模式。
- 預警群組只放我和 bot。
- 手動建立的活動維持核准流程；Agent 發的訊息不用核准。
- PR 流程照預設：每階段一個 PR、疊著做、等我 merge。
- 雲端資源：所有 PR 都開好後，給我一份照著做的建置指引。
- 未回覆的題目採預設：群組人數未知所以 Agent 每天上限 20 次；額度在 70%、90% 時預警，保留 5%；資料保存 180 天；給 Agent 的媒體連結 7 天有效。

---

## A. 群組與收訊

**A1 群組開關**
- 我想要：在後台決定每個群組要不要開放給 Agent。
- 以便：只有我同意的群組，內容才會送到外部 AI。
- 驗收條件：
  - 每個群組有一個「允許 Agent 讀取」開關，預設關閉。
  - 關閉的群組：不送給任何 Agent，Agent 也查不到它的內容。

**A2 收下所有類型的訊息**
- 我想要：開放的群組裡的文字、圖片、影片、語音、檔案都被 WiPPY 存下來。
- 以便：Agent 可以看到完整內容。
- 驗收條件：
  - LINE 會在一段時間後刪除媒體，所以收到就立刻下載保存；下載失敗會自動重試。
  - 單一檔案超過 50MB：只記錄檔名、大小、誰傳的，不下載。
  - 貼圖、位置只存基本資訊（貼圖編號、座標）。
  - bot 加入群組之前的訊息拿不到。這是 LINE 的限制。

**A3 自動清理**
- 我想要：訊息和媒體保存 180 天後自動刪除。
- 以便：控制成本和隱私風險。

## B. 前處理（白話說明）

「前處理」的意思是：Agent 不用自己讀幾百則原始訊息，WiPPY 先用免費模型幫它整理成一份「重點整理」。

**B1 重點整理**
- 系統每隔一段時間（由規則決定，例如每 30 分鐘）把群組的新訊息交給免費模型，產生一份整理，包含：
  - 一段摘要：這段時間大家在聊什麼。
  - 重點清單：誰提了什麼問題、有沒有待辦、提到的日期、時間、地點、金額。
  - 分類標籤：例如「活動」「問題」「抱怨」「緊急」。
- 這份整理連同原始訊息的連結，一起交給 Agent。

**B2 媒體怎麼整理**
- 圖片：模型看得懂圖片的話，寫一句說明，例如「活動海報，日期 11/20，地點台北」。看不懂就只列檔案資訊。
- 影片、語音、檔案：不轉成文字，只列「誰傳的、檔名、大小、下載連結」，由 Agent 自己決定要不要打開。

**B3 免費模型額度用完**
- 跳過整理，直接把原始訊息交給 Agent，流程不中斷。
- 後台記錄這次是「未整理」。
- 呼叫模型會控制間隔和次數，不超過免費版的限制。

## C. 規則：我決定什麼時候通知 Agent

**C1 建立規則**
- 我想要：在後台用表單建立規則。
- 驗收條件：規則可以設定：
  - 哪些群組。
  - 觸發條件：出現關鍵字、某種訊息類型（例如有人傳檔案）、有人 @bot、定時（每 N 分鐘）、訊息量（X 分鐘內超過 Y 則）。
  - 交給 Grok Bot 還是 Instinct。
  - 附什麼內容：重點整理、原文、媒體連結。
  - 給 Agent 的指令。
  - 冷卻時間：觸發後 N 分鐘內不再觸發。

**C2 規則命中，交給 Grok Bot**
- 驗收條件：
  - WiPPY 呼叫 Grok Bot 的 Routine webhook，帶上內容、工作編號，以及完成後的回報方式。
  - 呼叫失敗會自動重試。

**C3 規則命中，交給 Instinct**
- WiPPY 叫不到 Instinct，所以改成把這件事放進 **Instinct 的收件匣**，等它下次登入時處理。
- 驗收條件：收件匣項目超過 N 小時（預設 24 小時）沒處理，發預警給我。

## D. Grok Bot

**D1 Grok Bot 主動查詢**
- Grok Bot 透過 MCP 或 API 可以查：
  - 開放的群組列表
  - 群組訊息（可依時間、類型篩選）
  - 關鍵字搜尋
  - 重點整理
  - 媒體連結
  - 已存的紀錄
  - 本月 LINE 額度

**D2 Grok Bot 送出執行要求**
- 它可以要求 WiPPY：發訊息到群組、發預警、存一筆紀錄、排程訊息、把它做好的網頁或媒體發到群組。
- 不需要我核准，WiPPY 直接執行，但要通過第 G 節的額度檢查。

**D3 不重複執行**
- 同一個要求重送多次，WiPPY 只執行一次，不會重複發訊息、重複扣額度。

## E. Instinct（用後台帳號）

**E1 專屬帳號**
- 我想要：在後台為 Instinct 建一組 Email 和密碼帳號。
- 驗收條件：
  - 這個帳號只能看到開放群組的資訊、處理收件匣、執行動作。
  - **不能**改設定、Agent、規則、群組開關，也不能新增帳號。

**E2 Agent 工作台**
- Instinct 登入後看到一個「工作台」，裡面有：
  - 收件匣：待處理項目
  - 各群組的重點整理
  - 訊息搜尋
  - 紀錄
- 畫面要簡單、按鈕文字明確、不需要複雜操作，方便 AI 用瀏覽器操作。

**E3 在工作台執行動作**
- Instinct 用表單可以：發訊息、發預警、存紀錄、貼上網址發送到群組、上傳圖片或影片或檔案後發送到群組。
- 處理完的收件匣項目可以標記「完成」。

**E4 我看得到它做了什麼**
- 我想要：看到 Instinct 和 Grok Bot 做過的每一個動作。
- 驗收條件：每筆都記錄時間、內容、結果。

**E5 禁止陌生人註冊**
- 現在登入頁任何人都能註冊。
- 改成：只有我和我建立的 Agent 帳號能登入。

## F. Agent 做的網頁或媒體，發到群組

Grok Bot 和 Instinct 會在**它們自己那邊**做好網頁或媒體，產生**它們自己的網址**。WiPPY 不製作內容，只負責發到群組，並確保成員打得開。

**F1 發送前先檢查網址**
- Agent 給 WiPPY 一個網址和目標群組。
- WiPPY 先用「沒有登入」的狀態打開這個網址檢查：
  - 打得開：發一張連結卡片到群組（標題、說明、按鈕）。
  - 打不開（需要登入、已過期、錯誤）：不發送，並告訴 Agent 和預警群組原因。

**F2 想在 LINE 裡直接顯示圖片或影片**
- LINE 要求「直接指向檔案」的 https 網址，而且有大小和格式限制，例如圖片 ≤ 10MB。
- Agent 的網址符合規格：直接用它的網址發送。
- 不符合（例如是分享頁，或可能會過期）：WiPPY 下載一份存到自己的空間，再發送。

**F3 上傳檔案**
- Instinct 在工作台上傳的檔案，WiPPY 存在自己的空間，產生公開連結後發送。
- LINE 不能直接發「檔案」，所以一律改成連結卡片。

## G. LINE 推播額度

**G1 額度預警**
- 每小時查一次 LINE 本月的額度和用量。
- 用到 70%、90% 時各發一次預警到預警群組（只有我和 bot，每次只扣 1 則）。

**G2 額度守門**
- 每次發送前估算會扣幾則：發到群組時，按群組人數算。
- 剩不到 5% 時，擋下 Agent 的發送，只留給預警用。
- 每個 Agent 每天最多發 20 次（可以調整）。
- 被擋下的發送要告訴 Agent 原因。

**G3 後台儀表板**
- 顯示本月額度、已用量、預估月底用量、免費模型今天的用量。

## H. 失敗與重試

**H1 自動重試**
- 呼叫 Grok Bot、下載媒體、發送 LINE 失敗時，自動重試，間隔逐漸拉長，最多 8 次。
- 最後仍然失敗：發預警給我，我可以在後台手動重試。

## I. 活動推播整合

**I1 Agent 排程訊息**
- Agent 可以要求「某個時間發某段話到某個群組」。
- 直接生效，用現有的排程發送機制。

**I2 手動活動不變**
- 我手動建立的活動維持現在的流程：AI 規劃、我核准、才發送。

## J. 後台設定頁

**J1 新增的頁面**
- Agent 管理：Grok Bot 的連線設定、API key、MCP 設定說明、Instinct 帳號管理。
- 規則管理
- 預警與額度
- 紀錄查詢
- 執行紀錄：所有派送和動作的狀態，可以手動重試。

## K. 雲端建置指引

**K1 建置指引**
- 所有 PR 開好後，我會收到一份照著做就能完成的指引，內容包括：
  - Cloud Storage
  - Cloud Tasks
  - 排程 job
  - Grok Bot 的 Routine 和 MCP 設定
  - 建立 Instinct 帳號
- 每一步都說明「做什麼、為什麼、怎麼確認做對了」。
