# WiPPY Agent Hub 規格（草案 v0.1）

- 日期：2026-11-04
- 狀態：等待使用者確認「第 9 節 待確認問題」；未回覆的題目採用各題「預設」

- 開發方式：TDD，每階段一個 PR，merge 由使用者決定

---

## 1. 目標

WiPPY 成為「LINE 群組 ↔ 外部 AI Agent」的中樞：

1. **收**：接收 LINE 群組內的文字、圖片、影片、語音、檔案，存進 WiPPY。
2. **整理**：用 WiPPY 現有的免費模型 API 做初步整理（摘要、分類、重點）。
3. **轉**：依使用者自訂的規則，把內容轉給外部 Agent（第一個是 xAI Grok Bot）。
4. **被查**：Agent 可以主動呼叫 WiPPY 查訊息、摘要、媒體、紀錄。
5. **執行**：Agent 判斷後送出「執行要求」，由 WiPPY 執行：發訊息、發預警、記錄、排程訊息，以及把 Agent 做好的網頁或媒體傳到指定群組，並確保群組成員打得開。

非目標：

- WiPPY 不製作網頁或媒體，只負責接收、託管、發送。
- 不支援多使用者。
- 不做 Agent 端的邏輯；判斷由 Agent 自己負責。

## 2. 外部系統調查結果

### 2.1 xAI Grok Bot

- Grok Bot 是 xAI 的雲端 Agent 產品，2026-08 進入 beta，跑在自己的雲端電腦上。
- **WiPPY → Grok Bot**：Grok Bot 的 Routine 可以用 webhook 觸發。
  - 每個 Routine 有一組 POST URL 和 key，呼叫時帶 `Authorization: Bearer <key>`，JSON body 會連同 Routine 指令一起交給 Bot。
  - 回 200 只代表「已接受並開始執行」，不代表做完，結果是**非同步**的。
- **Grok Bot → WiPPY**：
  - Grok Bot 可以在對話中加入自訂的遠端 MCP server（URL 加 header token）。
  - 社群做法是在 webhook payload 裡附 `jobId` 和 `callbackUrl`，Bot 做完後再呼叫回來。
- **沒有**官方 SDK，也沒有可直接驅動 Bot 的公開 API。
- 注意：xAI 另有「Grok automations」webhook（HMAC 簽章、回 202），跟 Bot Routine 不是同一套，不要混用。

**結論：** 同時做兩條路，不依賴 xAI 未公開的功能：

- WiPPY 用 Routine webhook 呼叫 Grok Bot，payload 附 `jobId` 和 `callbackUrl`。
- Grok Bot 用 WiPPY 提供的 **MCP server** 或 **REST API**（API key 驗證）呼叫 WiPPY。

### 2.2 Instinct

- Instinct 是 Spear Street Technology 的個人 Agent，目前只開放邀請制 beta。使用者透過 iMessage、WhatsApp 或電話跟它互動，它在雲端電腦上操作你連結的服務。
- **沒有公開的開發者 API 或 webhook**，也查不到 MCP 支援的官方說明。

**結論：** WiPPY 的連接器做成通用介面（webhook 呼出、REST/MCP 呼入）。Instinct 等確認它能呼叫 HTTP 或 MCP 後再接（見第 9 節 Q1）。第一階段以 Grok Bot 為主。

### 2.3 LINE Messaging API

| 項目 | 是否支援 | 說明 |
|---|---|---|
| 接收群組文字 | ✅ | bot 必須在群組內，並開啟「允許加入群組」。 |
| 接收圖片、影片、語音、檔案 | ✅ | webhook 只給 messageId，要另外呼叫 `GET api-data.line.me/v2/bot/message/{id}/content` 下載。 |
| 內容保存期限 | ⚠️ | LINE 會在「一段時間後」自動刪除，官方沒寫明多久。**收到 webhook 後要立刻下載**，並且要有重試。 |
| 影片、語音轉檔 | ⚠️ | 可能還沒準備好，要先查 `.../content/transcoding` 狀態，再延後重試。 |
| 相簿（多張圖） | ✅ | 每張圖是一個獨立事件，用 `imageSet` 串起來。 |
| 貼圖、位置 | ✅ | 只有貼圖 ID 或座標，沒有檔案內容。 |
| bot 加入前的歷史訊息、記事本、相簿 | ❌ | 拿不到。 |
| 發送文字、Flex（連結卡片） | ✅ | |
| 發送圖片 | ✅ | 要用 HTTPS URL，JPEG/PNG，原圖 ≤ 10MB；預覽圖 ≤ 1MB。 |
| 發送影片 | ✅ | 要用 HTTPS URL，mp4 ≤ 200MB，並附一張預覽圖。 |
| 發送語音 | ✅ | 要用 HTTPS URL，m4a，並附長度（毫秒）。 |
| 發送「檔案」 | ❌ | LINE 沒有檔案訊息類型，要改成「連結卡片」，指向 WiPPY 託管的檔案。 |
| 查額度 | ✅ | `GET /v2/bot/message/quota`、`GET /v2/bot/message/quota/consumption` |

**推播額度怎麼算（關鍵限制）：**

- push、multicast、broadcast 會計入額度；reply（回覆）不計入。
- **發到群組時，按群組人數計算**：一則訊息發到 10 人的群組，算 10 則。
- 台灣「輕用量（免費）」方案約每月 **200 則**（第三方資料，正式數字以 quota API 回傳為準）。
- 也就是說，在 10 人的群組，**整個月大約只能發 20 次**。
- reply 雖然免費，但 reply token 只在收到事件後短時間內有效。Agent 是分鐘級的非同步流程，大多用不到。

## 3. 架構

```
LINE 群組 ──webhook──▶ [1] 收訊 Ingest
                         │  存訊息（groupMessages）
                         │  媒體 → 下載任務 → Cloud Storage（私有）
                         ▼
                      [2] 規則引擎 Rules ◀── 定時 tick（批次規則）
                         │  符合條件 → 建立派送工作（agentDispatches）
                         ▼
                      [3] 前處理 Preprocess（免費模型，有速率限制）
                         │  摘要、分類、重點；超出限制就降級成原文
                         ▼
                      [4] 派送 Dispatch ──Routine webhook──▶ Grok Bot
                                                                 │
          ┌────────────── REST /api/hub/v1 或 MCP /mcp ◀─────────┘
          ▼
      [5] Agent API：查詢工具 + 執行要求（agentActions）
          ▼
      [6] 執行器 Executor（佇列、冪等、重試）
          │  發訊息、預警 → LINE 發送服務（額度守門）
          │  網頁、媒體 → 公開託管空間（獨立網域）→ 發到群組
          │  紀錄 → agentRecords；排程 → activityMessages
          ▼
      [7] 額度監控：定時查 quota → 到門檻就預警
```

### 3.1 非同步與重試

- 下載媒體、前處理、派送給 Agent、執行要求，全部走**工作佇列**。
- 正式環境用 Cloud Tasks；本機和測試用 inline 佇列，同一個介面可以替換。
- 重試採指數退避，最多 N 次（預設 8 次，最長間隔 10 分鐘）。超過次數就標記 `failed` 並發預警。
- 每筆工作都有**冪等鍵**（idempotency key），同一個要求重送也只會執行一次，避免重複發訊息、重複扣額度。
- LINE webhook 用 `webhookEventId` 去重，因為 LINE 可能重送同一個事件。

### 3.2 免費模型的速率限制

- 沿用現有的 `llmProvider`（目前是 Gemini API 上的 `gemma-4-26b-a4b-it`，免費）。
- Google 沒公開 Gemma 免費版的 RPM、RPD 上限，以 AI Studio 專案頁的數字為準。所以做成可設定：
  - `LLM_MAX_RPM`：每分鐘上限，預設 **10**
  - `LLM_MAX_RPD`：每日上限，預設 **500**
  - `LLM_MIN_INTERVAL_MS`：兩次呼叫最短間隔，預設 **6000**
- 全域的 token bucket 存在 Firestore，所有呼叫 LLM 的地方（包括現有的活動 AI 對話）共用。
- 遇到 429 錯誤：依 `Retry-After` 延後，把工作重新排回佇列。
- **降級**：當日額度用完時，前處理改成「不摘要、直接送原文」，Agent 流程不會中斷。

### 3.3 公開託管（確保群組成員打得開）

- Agent 給的媒體或網頁，WiPPY 一律**下載一份到自己的空間**再發送，不直接轉 Agent 的網址，因為 Agent 的網址可能是私有的或會過期。
- **安全**：Agent 產生的 HTML **不能**放在 `wippy-mvp.web.app`。那是後台網域，惡意 HTML 可以讀取登入狀態（XSS）。
- 改放在**獨立網域**：一個公開讀取的 Cloud Storage bucket，透過 `https://storage.googleapis.com/<bucket>/...` 存取。路徑用無法猜測的隨機 ID。
- 圖片若大於 1MB，另外產生一張 ≤ 1MB 的預覽圖。
- LINE 傳進來的原始媒體放在**私有** bucket。給 Agent 時用有期限的簽名網址（預設 7 天）。

## 4. 資料模型（Firestore）

| Collection | 用途 | 主要欄位 |
|---|---|---|
| `groups/{groupId}`（擴充） | 群組 | 新增 `agentEnabled: boolean`（預設 false）、`agentEnabledAt` |
| `groupMessages/{eventId}` | 原始訊息（所有類型） | `groupId, senderId, senderName, type(text/image/video/audio/file/sticker/location), text, fileName, fileSize, mediaAssetId, lineMessageId, imageSet, timestamp, ttl` |
| `mediaAssets/{id}` | 媒體檔案 | `source(line/agent), visibility(private/public), storagePath, contentType, size, status(pending/ready/failed), attempts, publicUrl, previewUrl, durationMs, ttl` |
| `agents/{agentId}` | Agent 連接器 | `name, type(grok_bot_routine/generic_webhook), webhookUrl, secretRef, inboundKeyHash, enabled, allowedGroupIds[], dailySendLimit, createdAt` |
| `agentRules/{ruleId}` | 規則 | `name, enabled, agentId, groupIds[], trigger, preprocess, payload, cooldownMinutes` |
| `agentDispatches/{id}` | WiPPY→Agent 派送 | `ruleId, agentId, groupId, messageIds[], digest, status(queued/sent/failed), attempts, lastError, callbackToken` |
| `agentActions/{idempotencyKey}` | Agent→WiPPY 執行要求 | `agentId, dispatchId?, type, params, status(queued/running/done/failed/blocked), result, attempts, lastError` |
| `agentRecords/{id}` | Agent 記錄的重點資訊 | `agentId, groupId?, category, title, content, tags[], sourceMessageIds[], createdAt` |
| `hubSettings/{ownerId}` | 全域設定 | `alertGroupId, quotaWarnPercents[70,90], quotaReservePercent(5), retentionDays(180), llmLimits` |
| `lineQuotaSnapshots/{yyyyMM}` | 額度紀錄 | `limit, used, checkedAt, warnedLevels[]` |
| `llmUsage/{yyyyMMdd}` | 模型用量 | `count, minuteWindow...` |
| `actionLogs/{id}` | 稽核紀錄 | 誰（哪個 Agent）在何時做了什麼、結果如何 |

規則 `trigger` 的類型：

- `keyword`：內容包含關鍵字，或符合 regex
- `message_type`：例如「任何檔案」「任何圖片」
- `mention`：有人 @ 機器人
- `schedule`：每 N 分鐘把新訊息打包成批次
- `volume`：X 分鐘內超過 Y 則訊息

`payload` 的選項：要帶原文、摘要或媒體連結，要帶最近幾則上下文，以及給 Agent 的指令範本。

所有 collection 都只開放後端讀寫，前端一律透過 API 存取。

## 5. Agent API（Agent → WiPPY）

驗證方式：每個 Agent 一把 API key，資料庫只存 hash。帶法是 `Authorization: Bearer <key>`，或 MCP 的 header。

REST 路徑前綴是 `/api/hub/v1`；MCP 是 `/mcp`（Streamable HTTP），兩邊提供同一組工具。

### 5.1 查詢工具（給「Agent 主動搜」用）

| 工具 | 說明 |
|---|---|
| `list_groups` | 已開啟 Agent 的群組（名稱、人數） |
| `get_messages(groupId, since?, until?, types?, limit≤200)` | 原始訊息，媒體附簽名網址 |
| `search_messages(query, groupIds?, since?)` | 關鍵字搜尋 |
| `get_digest(groupId, since)` | 取得或產生摘要（受速率限制） |
| `get_media(mediaAssetId)` | 簽名網址加 metadata |
| `list_records(filter)` | 查已存的紀錄 |
| `get_quota` | LINE 本月額度、已用量、預估 |

### 5.2 執行要求

每個要求都必須帶 `idempotencyKey`。

| 動作 | 說明 |
|---|---|
| `send_message(groupId, text)` | 發文字；**不需核准**，直接發 |
| `send_alert(text, severity)` | 發到預警群組 |
| `send_image(groupId, url \| base64, alt?)` | WiPPY 下載 → 公開託管 → 發圖片訊息 |
| `send_video(groupId, url, previewUrl?)` | 同上，發影片訊息 |
| `send_audio(groupId, url, durationMs?)` | 同上，發語音訊息 |
| `publish_page(html, title)` → `{url}` | 把 Agent 做好的 HTML 託管到獨立網域 |
| `send_link(groupId, url, title, description?, imageUrl?)` | 發 Flex 連結卡片，適用網頁和一般檔案 |
| `record(category, title, content, tags?, groupId?, sourceMessageIds?)` | 存一筆紀錄 |
| `schedule_message(groupId, text, sendAt)` | 寫入活動推播的排程 |
| `complete_dispatch(jobId, summary?, actions[]?)` | Routine 的 callback：結束一次派送，可同時附帶多個執行要求 |

**守門條件**（擋下時狀態標 `blocked`，並回傳原因）：

- Agent 已停用，或目標群組不在 `allowedGroupIds` 內
- 目標群組沒有開啟 `agentEnabled`
- 超過 Agent 每日發送上限（預設 20 次）
- 本次發送後，LINE 額度會用到保留量以下（預設保留 5%，只給預警用）

## 6. 後台設定頁（網頁表單）

1. **群組**：每個群組加一個「允許送給 Agent」開關，預設關閉。
2. **Agent**：新增、編輯連接器（Routine URL、key、允許發送的群組、每日上限）；產生 WiPPY 的 API key（只顯示一次）；附 MCP 設定說明；「測試連線」按鈕。
3. **規則**：用表單設定觸發條件、目標群組、Agent、要帶的內容、冷卻時間；可以啟用或停用。
4. **預警與額度**：選預警群組、設定門檻；顯示本月額度用量和模型用量。
5. **紀錄**：`agentRecords` 列表，可篩選、搜尋。
6. **活動記錄**：派送和執行要求的狀態、錯誤、重試次數，可以手動重試。

## 7. 成本評估（每月）

**假設：** 5 個群組、每天共 300 則訊息、30 張圖、5 個檔案、10 次派送給 Agent，媒體保留 180 天，每個群組 10 人。

| 項目 | 用量估計 | 免費額度 | 預估費用 |
|---|---|---|---|
| Firestore 寫入 | 約 1,500 次/天 | 2 萬次/天 | US$0 |
| Firestore 讀取 | 約 5,000 次/天 | 5 萬次/天 | US$0 |
| Firestore 儲存 | 文字約 10MB/月 | 1 GiB | US$0 |
| Cloud Storage 儲存（asia-east1） | 每月新增約 0.5GB，180 天後穩定在約 3GB | 亞洲區無免費額度 | 約 US$0.01–0.07 |
| Cloud Storage 流量（成員打開媒體） | 約 4–5GB/月 | — | 約 US$0.5 |
| Cloud Run、Cloud Tasks、Scheduler | 遠低於免費額度 | 有 | US$0 |
| Gemini 免費模型 | 受 RPD 限制 | 免費 | US$0 |
| LINE 推播 | 免費方案約 200 則/月 | — | NT$0（超過要升級方案） |

**合計：約 US$0.5–1/月（約 NT$15–35）。**

- 主要變數是媒體量和群組成員打開的次數。
- 存在目前的資料庫**可行**。
- 真正的瓶頸是 **LINE 免費推播額度**，不是儲存成本。

## 8. 分階段計畫（每階段一個 PR，TDD）

| 階段 | 內容 | 驗收（自動化測試） |
|---|---|---|
| P1 收訊基礎 | 群組開關；所有訊息類型寫入 `groupMessages`；媒體下載佇列（含轉檔狀態和重試）；webhook 去重；保存期限欄位 | webhook 各類事件 → 正確的資料；下載失敗會重試；未開啟的群組不送 Agent |
| P2 發送與額度 | LINE 發送服務（文字、圖片、影片、語音、Flex），按群組人數估算額度；額度守門；定時查額度並預警；公開託管 bucket | 額度到門檻 → 預警一次；低於保留量 → 擋下；媒體網址符合 LINE 規格 |
| P3 規則與派送 | 規則引擎（5 種觸發）；LLM 速率限制和降級；前處理；Grok Routine 派送（Bearer、jobId、callbackUrl）；重試 | 規則命中、冷卻；429 → 延後重排；派送失敗會重試，最後轉預警 |
| P4 Agent API | REST 和 MCP 工具；API key；執行要求佇列；冪等；callback；稽核紀錄 | 未授權 → 401；同一冪等鍵只執行一次；每個動作的守門條件 |
| P5 後台 UI | 第 6 節的六個頁面 | 元件測試：表單驗證、狀態顯示 |
| P6 整合與收尾 | 活動推播整合（`schedule_message`）；保存期限清理排程；runbook（雲端設定步驟） | 排程訊息經現有 tick 發出；過期資料被清除 |

需要你在雲端手動做的事（我會寫進 runbook，這個環境無法直接操作 GCP）：

- 建立私有和公開的 Cloud Storage bucket
- 建立 Cloud Tasks queue
- 新增 Cloud Scheduler job（額度檢查、批次規則 tick、清理）
- 在 Grok Bot 建立 Routine，並加入 WiPPY 的 MCP server

## 9. 待確認問題（未回覆就採用「預設」）

1. **Instinct**：它沒有公開 API。你有使用權嗎？它能呼叫外部 HTTP 或 MCP 嗎？
   - 預設：先做通用連接器加 Grok Bot，Instinct 等確認後再接。
2. **Grok Bot 權限**：你的方案能建立 Routine 的 webhook，並在對話中加入自訂 MCP server 嗎？
   - 預設：可以。
3. **預警群組怎麼建（重要）**：發到群組是按人數扣額度，所以預警群組最好只有你和 bot，每次預警只扣 1 則。
   - 預設：建一個只有你和 bot 的「WiPPY 預警」群組。
4. **推播額度不夠用**：10 人群組每月大約只能發 20 次。你的群組大約幾個人？
   - Agent 每日發送上限，預設 20 次。
   - 額度預警門檻預設 70%、90%；保留 5% 只給預警用。
   - 也請你評估是否升級 LINE 方案。
5. **保存期限**：原始訊息和媒體保存多久？
   - 預設：180 天，之後自動刪除。
6. **給 Agent 的媒體連結**：用有期限的簽名網址可以嗎？
   - 預設：有效 7 天。
7. **公開託管的網址**：Agent 做的網頁會放在 `storage.googleapis.com/<bucket>/<隨機ID>/...`，網址不好看，但安全，也不用買網域。可以接受嗎？還是你要用自己的網域？
   - 預設：先用 storage 網址。
8. **手動建的活動**：還要不要走核准流程？
   - 預設：手動建立的活動保留核准；Agent 排程的訊息直接核准。
9. **前處理範圍**：
   - 預設：文字做批次摘要和分類；圖片如果模型支援就產生說明；影片、語音、檔案只送 metadata 和下載連結，不轉文字。
10. **單一檔案大小上限**：LINE 使用者可以傳很大的檔案。
    - 預設：超過 50MB 只記 metadata，不下載。
11. **PR 流程**：
    - 預設：每階段開一個 PR，CI 綠燈後停下，等你 merge。
    - 下一階段會等前一個 merge 後才開始，還是要我疊在前一個分支上繼續做？預設**疊著做**（stacked PR），這樣你不在時也不會停工。
